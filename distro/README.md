# Download ReWord

This folder contains the ready-to-use ReWord program for Mac.

| File | Description |
|---|---|
| `ReWord-1.5.1-mac-arm64.zip` | The program. Download this file. |
| `ReWord-1.5.1-mac-arm64.zip.sha256` | The checksum of the zip file (optional check). |

## What's new in 1.5.1

- **Chapter numbers you choose.** Each chapter of an edited book has a **Chapter** menu for its number in
  the book, so the chapters you cite can be, say, 3 and 7. The chapter menus (Cite…, the citation's
  chapter, a file's chapter) show that number. Leave it at **—** to show no number.
- **The sidebar no longer scrolls.** Its buttons, search and filters stay in place; only the list under
  them scrolls, and the Writing list is tighter.

## What's new in 1.5

- **Many files per source.** A citation's PDFs (translations, other versions, chapters) show above the
  reader one line each, in Citations, Research and Verify. Click **⋯** on a file to give it a label
  such as *English translation*.
- **Chapter(s) in edited book**, a new kind of source next to **Book**: one citation holds an edited
  book and every chapter you use from it. When you cite it, a **Chapter** menu picks the chapter, and
  the citation is formatted as that chapter (Bluebook, APA and Chicago). Click the citation later to
  change the chapter.
- **Chapter PDFs**: mark a file as a chapter's, and Verify opens that chapter's PDF for a citation to it.
- Looking up a chapter's DOI now makes an edited book holding that chapter.

## What's new in 1.4.1

- **Scanned and OCR'd PDFs show their pages.** Pages stored as JBIG2 or JPEG 2000 images (common in
  scans) used to come up blank in the reader, with only the invisible OCR text to select.
- **Linked citations take one line each** beside a research note. A note with more than three shows the
  chosen source and an **All N ▾** button that drops the full list down over the reader, so the PDF
  keeps the height.
- **Narrow windows**: under about 900 pixels wide the sidebar floats over the page (the sidebar button
  shows it), and the editor and preview, or a note and its sources, stack top to bottom. Each part
  still scrolls.
- **Id. in final drafts**: no more "*Id.*." when you type a period after the citation; *Id.* can lead a
  string citation; and in law review footnotes *Id.* is not used when the previous footnote cited more
  than one authority (Bluebook R4.1).

## What's new in 1.4

- **Part of ReSuite**, with RePublish, RePDF and the ReSuite hub, and a new icon from the same family.
  Each app still works on its own.
- **Make slides, a poster or a handout in RePublish** from the open document: click ReWord at the top
  of the sidebar, or use the File menu.
- **Open the finished PDF in RePDF**, and **⌃⌥⌘0–3** to move between the hub and the apps.
- **Highlights from RePDF become a research note** quoting each passage with its page.
- **One window glass setting** for every ReSuite app (View → Appearance → Translucent Window).

## What's new in 1.3.2

- **Research notes link to several citations**, and a citation can be linked to several notes. Notes
  you already have keep their source.
- **Linked citations beside every note**: the Research tab shows a card for each linked source, with the
  chosen one's PDF or saved web page and its highlights, in place of the Editor/Split/Preview page view.
- **Add several new sources at once**: in the new-note dialog (Add this source and start another), and
  from an open note (+ New… → Add, link and start another).
- **Export project bibliography** in the Citations tab: one Markdown file of the project's sources with
  their details, DOI and links, whether a copy is on file and where to look, written so an AI assistant
  can go and find each document.

## What's new in 1.3.1

- **A see-through window**, like the Mac's own apps: what's behind ReWord shows through, softly blurred,
  around the glass panels. View → Appearance → Translucent Window turns it off.
- **Save outside Writing** sits by the save status at the bottom of the sidebar instead of alone in the
  toolbar. In Writing it leads the toolbar as before.
- **A clearer Verify queue**: progress at a glance, citations under their sections with ✓ and ✕ marks,
  a map of a long pass with a marker where you are, and a right-click menu on each row. Other citations
  in a footnote now read as citations instead of tags.
- **A light facelift**: softer focus rings, a subtitle under each view's name, glass toasts, one
  Download menu for a document's finished files.
- **Citations that printed wrong now print right**: short forms of Westlaw cases typed into the docket
  number, rules cited to the Federal Register, plural abbreviations (Proc. Nat'l Acad. Sci.), article
  numbers, doubled periods, Chicago short titles and quoted titles.
- **Fixes that keep your work safe**: opening a document no longer rewrites its files; saving a source
  keeps fields its form doesn't show; Return and paste in a table keep it in one piece; Verify never
  loses or skips a result; Copy Subject uses the email's own details.

## What's new in 1.3

- **Verify.** A new tab (⌘4) for cite-checking. Pick a project and go through every citation one card at
  a time: the citation in context on the left (the sentence a footnote supports, the footnote, the
  pinpoint) and the source's PDF or web snapshot on the right. **Approve** (A) or **Send back** (F) with an
  optional reason. At the end, the summary lists what you sent back so you can fix each one and approve
  it. Results are saved with the project, and an approval resets if you later change that citation.

## What's new in 1.2.1

- **Cited in.** Each source's page in Citations lists every document and research note that cites it,
  with the section, the footnote number and the words around it. Click one to go straight there.
  The source list shows how often each source is cited, and **Not cited yet** finds the unused ones.
- **Find and Replace** (⌘F, ⇧⌘H) in documents, footnotes and notes; ⌘Z undoes a replacement.
- **A live word count** in the inspector, with footnotes counted separately and the template's limit.
- **Cite… and Footnote work in Markdown mode** too.
- **Save tells the truth about GitHub**: it shows when it couldn't sync, brings in changes made on your
  other computers right away, and asks about files changed in both places.
- **Fixes:** right-click Highlight in the PDF reader, ⌃⌘S no longer also saves, narrative citations in
  research notes, notes export in their project's citation style, and more.

## What's new in 1.2

- **A new look.** A floating glass sidebar holds Writing, Research, Citations, the project menu and
  your documents. One toolbar has Save, formatting, Cite, Footnote and the layout. An inspector on
  the right shows the document's settings, finished files, data folder and backups. Three
  appearances: Light, Dark, and Dark with a white page (View → Appearance).
- **The menu bar does the rest.** Insert, Format and View menus replace the old Insert and View
  tabs. View → Files opens the data folder, the repository on GitHub, and the backups.
- **Split view** shows the editor beside the preview (the preview is now the first tab).
- **Twelve highlight colors with your own labels**, set in project setup and shared by all projects.
- **Citations** shows the PDF in the middle and the citation's fields on the right.
- **Save shows its progress**: saved, built, copied to outputs, synced.

## What's new in 1.1.4

- **One button.** **Save** (⌘S) now saves, builds the open document, copies its finished files into
  `outputs/`, and syncs with GitHub. The separate Run, Publish and Sync buttons and the Publish tab
  are gone.
- **View → Files** opens the data folder (the folder that is your GitHub repository), the
  repository on GitHub, and the backup folder.

## What's new in 1.1.3

- **You choose when a file changed in two places.** ReWord gets GitHub's changes when it starts and
  keeps everything. If the same file was changed on this Mac and on GitHub, ReWord asks you to keep
  this Mac's version, GitHub's, or both.
- **Automatic backups.** After every successful sync, ReWord copies your work into
  `~/Library/Application Support/ReWord Backup`, a plain folder that is not on GitHub. The Publish
  tab shows where it is; **Show backups** opens it in Finder (in 1.1.4: **View → Files**).

## What's new in 1.1.2

- **Your work is in one place.** ReWord keeps your documents, research, sources and finished files
  in `~/Library/Application Support/ReWord`, in one folder and one git repository. The first time
  1.1.2 starts, it copies your existing `ReWord Data` folder there and leaves the original
  untouched. **Publish → Show data folder** opens it in Finder.
- **Safer syncing.** ReWord syncs with GitHub every 10 minutes while it is open (as well as on
  open, after Run and on quit). It recovers from an interrupted sync, and it joins histories that
  don't share a start instead of refusing, so changes made on GitHub are never left behind.

## What's new in 1.1.1

- **Attach PDF… works in the Mac app.** The **Attach PDF…** button in Citations now opens a file
  chooser so you can pick the PDF.
- **A right-click menu that fits what you click.** Text, citations, footnotes, the document tree,
  research notes, the citation library and the PDF reader each have their own menu. Hold Option
  while you right-click to see the standard Mac menu.

## What's new in 1.1

- **Change a document's template.** Open **Details** and choose another template, for example to
  turn a law review article into an APA assignment. Citations convert to the new style automatically.
  See section 7.1.1 of the [main README](../README.md).
- **Journal submission templates** in APA 7th, Chicago notes and bibliography, and Chicago author-date.
- **Chicago style** for every source in your library, also available in the annotated bibliography
  and as a project's citation style.

## Requirements

- A Mac with Apple Silicon (M1 or newer). To check: Apple menu > About This Mac. "Chip" must
  show "Apple M…". ReWord does not run on Intel Macs, Windows or Linux.
- macOS 12 (Monterey) or newer.
- About 400 MB of free space.

You do not need other software. ReWord contains its own copies of Python, Pandoc and a TeX engine.

## Install

1. Open the [latest release](https://github.com/briannarimm/legal-writing-app/releases/latest) and click `ReWord-1.5.1-mac-arm64.zip` under
   **Assets**. The download starts. The file is about 90 MB. (The same file is in the list above:
   click it, then the **Download raw file** button.)
2. Download `ReWord-1.5.1-mac-arm64.zip.sha256` too if you want to check the download (below).
3. Open your Downloads folder. Double-click the zip file. A folder named `ReWord` appears.
4. Move `ReWord.app` to your Applications folder, or the whole `ReWord` folder to a USB drive.
5. Double-click `ReWord.app`.

### If macOS says it cannot verify the app

ReWord is not signed with a paid Apple Developer certificate. Thus, macOS shows a warning the
first time you open it.

1. Click **Done** (or **Cancel**) in the warning.
2. Open **System Settings > Privacy & Security**.
3. Scroll to the message about ReWord. Click **Open Anyway**.
4. Enter your Mac password if macOS asks for it. Click **Open**.

On macOS 14 and older, you can also right-click `ReWord.app`, select **Open**, then click **Open**.

You do this one time only.

## Check the download (optional)

Open Terminal, go to the folder that contains the zip file, and run:

```bash
shasum -a 256 -c ReWord-1.5.1-mac-arm64.zip.sha256
```

The result must be `ReWord-1.5.1-mac-arm64.zip: OK`. If the result is different, delete the file
and download it again.

## Your data

ReWord saves your documents, notes, sources and finished files in
`~/Library/Application Support/ReWord`. **View → Show Data Folder in Finder** opens it. When ReWord runs
from a USB drive, it uses a `ReWord Data` folder next to the app instead. ReWord does not send your
work to the internet unless you connect GitHub (see section 10 of the
[main README](../README.md)).

To update ReWord, replace only `ReWord.app`. Your data folder is not touched.

## For maintainers: make a new download

1. Change `VERSION` in `scripts/make_app.py`.
2. Run `make dist` on an Apple Silicon Mac with the Xcode command line tools.
3. Delete the old zip and checksum files from this folder. Commit the new ones.

The zip must stay smaller than 100 MB. GitHub refuses larger files in a repository. If the zip
becomes larger, attach it to a GitHub Release instead.
